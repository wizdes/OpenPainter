How OpenPainter is built

A simple, fast photo editor for the Mac, built in the spirit of paint.net. The pixel engine is Rust, so it can move to Windows and Linux later. The Mac app is Swift.

What I need from you: nothing right now. This page is for reading. Building has started. The "Choices to check" list near the end shows the defaults I picked. Tell me if any of them is wrong, and I will change course.

The two halves

OpenPainter has two parts. The Mac app draws the windows and passes on what you click. The engine holds the image and does all the pixel math. They talk through a small C interface. Every action, such as "Gaussian blur radius 4", is one named command. Menus, shortcuts, the History panel, tests and a command-line tool all send the same commands.

How undo stays cheap and exact

Each layer is cut into 256×256 tiles. When an edit changes a tile, it makes a new copy of that tile. Every tile it did not touch is shared with the step before. So a small brush stroke on a 24-megapixel photo costs a few tiles, not the whole layer. Undo just points back to the older set of tiles. It also brings back the selection and the active layer. When memory gets tight, old history tiles are compressed and then written to disk.

How "exactly right" is checked

Each image operation is tested against a known-correct result. Two outside reviews showed that one reference cannot serve every operation: paint.net 5 rewrote most effects, and its old integer math differs from modern float math. So every operation gets a row in a target table. The row says which paint.net version it copies, which reference proves it, and how close it must be (usually 1 step out of 255 per channel).

5.1 Real paint.net 5.1.12

Pinned on your Windows PC. Captured outputs (saved PNGs, never screenshots) for every effect whose behavior changed in paint.net 5.

3.36 The paint.net 3.36 code, actually run

The MIT source compiled and run in a Linux VM, so ported effects are checked against the real old code, not against a copy of it.

f64 Exact formulas

Layer blending follows your float-math choice. It is checked against a 64-bit formula. Brushes, shapes and text are checked against reviewed images and geometry tests.

GPU CPU twin

Every GPU shader is compared against its CPU version on Apple's GPU, and also on Linux with a software GPU, so it can never drift.

Your decisions, and my defaults

You decided

  • Name OpenPainter; MIT; free signed download on GitHub plus a yili.dev page
  • macOS 15 or later; Rust engine, Swift UI
  • GPU effects from the start; 8-bit pixels, float math
  • Full color management
  • PNG, JPEG, BMP, GIF, TIFF, HEIC, WebP, AVIF, Camera RAW
  • Crop with aspect ratios, healing, content-aware fill, remove background
  • Destructive edits like paint.net, every step undoable
  • paint.net look: floating panels, image thumbnail strip, original icons
  • Pen pressure; all effects in paint.net order

Choices to check

  • GPU path is wgpu (runs on Metal, Vulkan, DirectX), with a CPU twin for every op
  • Pixel math runs on the image's own color values, as paint.net does, not in linear light
  • The layered file is .opaint, a standard OpenRaster zip that Krita and GIMP can open
  • Text uses Apple's CoreText; Windows and Linux get their own shaper later
  • paint.net captures run on your Windows PC; if that fails, paint.net 3.36 source plus Pinta
  • This Mac has 8 GB of RAM, so I run 2 builders at a time, not 3
  • Linux checks run in a small Linux VM on this Mac, not on the Linode server, which has 1 GB of RAM and runs your sites
  • The target is paint.net 5.1.12, pinned. 5.2's 8 new effects are not in version 1
  • Layer blending uses float math (your choice), as paint.net 5.2 does, not 3.36's integer rounding
  • The plan grew to 60 milestones and about 620 agent hours after the reviews
