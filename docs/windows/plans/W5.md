# W5: UI stack test

Tier 3: this choice sets 182 hours of later UI work. Budget: 14 agent hours. Needs: W3, decision 4 (given).

W5 builds the same small shell twice, once in Avalonia 12 and once in WinUI 3, both as NativeAOT builds. Root then runs both on real windows and fills one table. Avalonia stays the pick unless it fails a test in section 3.1 of `PLAN.md`. WinUI must pass the same list before it can replace Avalonia.

## What the shell does

Both shells open the same 1600 by 1000 test document in the engine and show:

| Part | What it must do |
| --- | --- |
| Canvas | The engine draws it, through `op-ffi`. |
| Marching ants | An animated dashed rectangle over the canvas, a crop dim and a text caret. |
| Floating panel | A movable panel that stays above the canvas. |
| Menu and dialog | One menu that opens over the canvas, and one modal dialog with a number box. |
| Input on the canvas | Pointer, wheel, keyboard and typed text (including a dead key) land in a log, with pressure and the pointer type. |
| Focus | Tab moves focus from the panel to the canvas and back, and the canvas shows it. |
| Accessibility | The canvas, panel and menu have names that UI Automation and Narrator can read. |

Each stack draws its overlays its own way. WinUI draws XAML over a `SwapChainPanel`. Avalonia cannot draw over a native child window, so the engine view shader draws them.

## What changes

| Item | Owner | Result |
| --- | --- | --- |
| `engine/op-ffi` | Builder | A DLL build, `op_view_attach_panel` for a `SwapChainPanel`, and `op_view_set_overlay` for the shader overlay. Windows only. No change to Mac behavior. |
| `tools/ui-spike/avalonia`, `tools/ui-spike/winui` | Builder | The two shells, each with a `--measure` mode that writes a JSON file. |
| `tools/ui-spike/tests` | Builder | Avalonia headless tests that run as `agent`, and a list of what they can and cannot see of the canvas. |
| `tools/ui-spike/run-window-checks.ps1` | Builder writes, root reads and runs | Runs each table row on a real window as `yjli`, on the hidden desktop where it can, and on the visible desktop otherwise. |
| `docs/windows/w5-spike.md` | Builder starts, root finishes | The table, filled from real runs. |
| `docs/windows/decisions.md`, `ARCHITECTURE.md` | Root | The choice, after the Astra and Fable votes. |

## What changed during the build

The builder has no window, so root fixed what the real-window runs found, in six rounds. The shells did not start at first: Avalonia had no program manifest, and WinUI had no `App.xaml` or generated start-up code. WinUI also needed the real panel interface and a bridge to the UI thread. The list is in `w5-spike.md`.

## Done-test

One table for both stacks, with no NOT RUN except a real pen: launch time, program size, resize, overlay frame rate, text input, pointer, focus, Narrator, and what headless tests see. All of it comes from AOT builds. UI Automation was tried again on the hidden desktop. Astra and Fable voted. The choice is written down.

## Not in this version

- Real tools, documents from disk, saving, settings, themes and icons. This code is thrown away or rewritten in W7.
- Matching the Mac layout. W7 does that, with the Mac app as the reference.
- A Store package or an installer.
- Any change to the Mac app.
