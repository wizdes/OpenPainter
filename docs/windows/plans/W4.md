# W4: paint.net capture kit

Tier 3: new test system; its results will change the engine's targets. Budget: 20 agent hours. Needs: W0, decision 4 (given).

## New facts from 2026-11-01

- As `yjli`, the pinned copy runs on a hidden desktop in session 2. A `PrintWindow` capture showed the full window, and nothing appeared on the user's screen.
- A second copy started while one runs exits with no new window. It hands off to the first copy. So a capture must never start while the user's copy runs: its work would land in their window.
- The pin was unpacked clean from the ZIP. `agent` can read it but not write it.
- The user's `%LOCALAPPDATA%\Paint.NET` is backed up at `C:\agent-work\pdn-user-backup-20261101`.

## What changes

| Item | Owner | Result |
| --- | --- | --- |
| Preflight | Builder | Fails at `checkpoint`, `speed` and a new `capture` level when any `paintdotnet*` process runs outside the pin. Reads process paths only. |
| `tools/pdn-capture/plugin` | Builder writes, root reads and builds | A plain paint.net effect plugin, on the public API in the pin's `.xml` docs only. Given a job file, it runs each built-in effect on an input image with stated parameters and writes the result. If that needs private types, the builder stops and says so. |
| `tools/pdn-capture/driver` | Builder writes, root runs | Starts the pin on a hidden desktop, opens the input, starts the plugin, waits, stops the pin by PID, and closes the desktop. It writes a manifest per run: paint.net build, parameters, ICC, input hash, GPU, driver, output hash. |
| Catalog | Root runs | `docs/windows/pdn-5.1-effects.toml`: each built-in effect with its parameters, names, ranges and defaults, as the public API reports them. Used to list effects, not to design UI. |
| Captures | Root runs | Private repo `wizdes/OpenPainter-oracle`. Images are never in the public repo. |
| `targets.toml`, `m54_parity.rs` | After W1 merges | `pdn-5.1` rows, and the parity test reads them. A row with no capture fails or prints NOT RUN. |
| `parity.md` | Root | Started, with effects rows. |
| Fallback list | Root | Effects the plugin path cannot run. Next route: UI Automation on the hidden desktop, then the OpenPDN oracle. |

## What changed during the build

The plugin API route failed: no public way gives a parameter token (details in `tools/pdn-capture/README.md`). Captures use the plan's next route: real menus through UI Automation on the hidden desktop, with the plugin writing the pixels.

## Done-test

1. One effect per family, run twice, gives the same hashes on the hidden desktop.
2. The manifest pins build, parameters, ICC, inputs, GPU and driver.
3. Catalog and fallback list are committed. No image is in the public repo.
4. A `pdn-5.1` row with no capture fails or prints NOT RUN, and never passes.

## Not in this version

- The full parameter matrix and engine fixes. Those are W14.
- Any tool or UI capture. The Mac app is the reference for UI.
- Decompiling, loading private code, or copying paint.net resources.
