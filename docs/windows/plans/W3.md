# W3: GPU and canvas on DX12

Tier 3: a new platform path through the GPU and the view host. Budget: 16 agent hours. Needs: W1, closed.

## What changes

| Item | Change |
| --- | --- |
| Backend | One pinned backend for both device paths. Effects use `Instance::default()` at `op-gpu/src/lib.rs:707`, and Vulkan is listed before DX12 here. The view host asks for Metal only at `op-ffi/src/view.rs:218`. Windows pins DX12, with a selector for WARP. Mac stays on Metal. |
| Backend assert | Each GPU test run fails unless DX12 or WARP really ran. |
| Test host | A small Win32 test host in `tools/` or an example, for root to run. Builders cannot show windows. |
| View | A window handle in `op_view_attach`. Display profile from Windows, and a note on how DWM color management treats our output. Mac view tests must keep compiling. |
| Device lost | A device-lost callback in the view host. `simulate_device_loss` only sets a flag, so it cannot prove recovery alone. Check whether `ID3D12Device5::RemoveDevice` removes only our device. If so, use it in a real test. |
| Long jobs | A guard against GPU jobs long enough to trigger a Windows GPU reset. |
| Shader compiler | Choose FXC or DXC, and record why. |

## Bugs to find, from W1

1. **A hang.** `op-engine/tests/engine.rs` spun at full CPU for over 30 minutes on 2026-11-02 while paint.net ran on the same GPU. Alone it passes in 1.62 s. `all_tiles_release_after_close`, `previews_commit_once_and_cancel_without_history` and `registered_effect_commands_and_preview_commit_once` were the tests running. Suspect GPU contention or a device reset leading to a busy loop.
2. **A crash.** `op-engine/tests/jobs.rs:461` ended twice with `STATUS_ACCESS_VIOLATION` with GPU creation on, and passed with `OP_FORCE_CPU=1`.
3. **The color table.** `lut_on_gpu_matches_cpu_trilinear_within_one_level` at `op-gpu/tests/presenter.rs:182` gave error 0.558 levels on Vulkan.
4. The rest of the `op-gpu` tests, which have not finished on Windows.

## Done-test

1. M54 matrix: 0 failures on RTX and on WARP, and the run fails unless DX12 or WARP ran.
2. Resize, switch and create-destroy scenarios ported from the Swift tests pass on the Win32 host. Root runs these.
3. Color within ΔE00 1 of direct lcms2 transforms.
4. A real device removal recovers the canvas, if `RemoveDevice` touches only our device.
5. The hang and the crash each have a cause and a test, or are written up as unresolved with what was tried.
